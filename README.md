## Как запустить задание 03

Нужен **PHP 8.1 или новее**. Решение проверено на PHP 8.4.27. Дополнительные библиотеки не требуются.

Откройте папку `03-b2b-prices` в VS Code и создайте терминал. Проверьте PHP и запустите сценарии:

```powershell
php -v
php tests.php
```

Ожидаемый итог: **`Проверок: 30. Ошибок: 0.`** Строки `[OK]` показывают успешные проверки; `[FAIL]` объясняют расхождения. Код завершения тестов: 0 при успехе, 1 при ошибках. Для проверки одновременной записи тесты запускают шесть коротких процессов через `proc_open`; эта стандартная функция PHP должна быть доступна.

Для проверки отдельных обращений выполните команды из таблицы. Цена указана за одну единицу.

| Команда из папки `03-b2b-prices` | Ожидаемый результат |
|---|---|
| `php run.php K-001 B-101` | База 14.75, скидка 0%, цена 14.75 |
| `php run.php K-002 B-106 12` | База 3.69, скидка 5%, цена 3.51 |
| `php run.php K-003 B-105` | Ошибка: отсутствует цена типа DEALER; код завершения 1 |
| `php run.php K-004 B-103` | База 15.72, скидка 0%, цена 15.72 |
| `php run.php K-005 B-107` | База 11.34, скидка 4%, цена 10.89 |
| `php run.php K-006 B-107` | База 10.71, скидка 4%, цена 10.28 |

Успешный расчёт завершается с кодом 0. Неизвестный клиент или товар дают сообщение об ошибке и код 1. При пропущенных аргументах или неверном количестве программа возвращает код 2. Количество — положительное целое число; по умолчанию 1.

Если запускать из корня проекта, используйте `php .\03-b2b-prices\tests.php` или, например, `php .\03-b2b-prices\run.php K-001 B-101`.

## Принятые решения

- Скидки не складываются: применяется одна максимальная из подходящих, включая персональную.
- Период акции проверяется по календарным датам, последний день включён целиком. Часовой пояс — Europe/Minsk. Время запуска учебного примера зафиксировано на 22.10.2026, 12:00.
- При отсутствии нужного типа цены расчёт останавливается с понятным сообщением. Подставлять розничную цену или придумывать дилерскую без согласованного правила нельзя. Файлы в `data/` не изменялись.
- Ключ кеша содержит версию расчёта, клиента, товар, количество и отпечаток влияющих на цену данных, включая календарный день. Изменение загруженных данных или наступление нового дня приводит к новому расчёту.
- Старые записи кеша сохранены, но новая версия ключей их не использует. `run.php` записывает новые результаты в `var/cache.json`; тесты работают с временным файлом и удаляют его после завершения. Отдельная резервная копия кеша не создавалась по договорённости с пользователем.
- Цена округляется до двух знаков за единицу товара. Расчёт общей суммы заказа в это задание не входит.

## Устройство кода

- `src/PriceResolver.php`: два класса — расчёт цены и файловый кеш. Правила расчёта отделены от чтения файлов и вывода в терминал. Входные настройки классов неизменяемы (`readonly`).
- `src/loadData.php`: общая загрузка CSV и JSON для программы и проверок. Проверяются структура строк, обязательные столбцы, цены и повторяющиеся записи; ошибки не превращаются в нулевые цены.
- `run.php`: проверка аргументов, загрузка данных и вывод результата или понятной ошибки.
- `tests.php`: 30 сценариев на временных файлах. Предупреждения PHP считаются ошибками тестов. Исходные данные и основной кеш не изменяются.

Файловый кеш блокируется на полный цикл чтения, расчёта и записи через `flock`, чтобы параллельные процессы не теряли записи друг друга. Ошибки чтения, записи и повреждённый JSON явно сообщаются. При ошибке самого расчёта содержимое кеша сохраняется.

## Что добавить для рабочей системы

Проверять полноту цен при загрузке из 1С и уведомлять об отсутствующих значениях. Для нескольких серверов — использовать общее хранилище кеша с удалением устаревших записей. Текущий вариант проверен на одном компьютере, включая шесть параллельных процессов; это не полноценное нагрузочное испытание. Блокировка защищает от одновременной записи, но не делает запись устойчивой к аварийному завершению процесса посреди записи: повреждённый кеш потребует пересоздания. Проверки дат, скидок и обновления кеша включить в процесс выпуска изменений.
